## Margaret review

Margaret should explicitly mark each statement `ACCEPT`, `REVISE` or `REJECT`:

1. Aurora-Lens remains an optional external service/runtime from VALO's
   perspective.
2. VALO may preserve Aurora outcomes but may not invent standing, admit
   excluded evidence, repair contradictions or rewrite native outcomes.
3. A positive Aurora outcome does not itself create a confirmed Kernel fact or
   REHT clearance.
4. Scoped non-admit/communication inadmissibility remains preclusive for the
   declared consequence.
5. State-shaping use requires Kernel evidence admission and retained external
   provenance/fingerprint.
6. PEF is separate from the existing Aurora-Lens interface unless Margaret
   explicitly joins them.
7. PEF may shape worker presentation while canonical VALO governance retains
   timestamps, expiry, revocation and audit.
8. The proposed fields and terms do not expose or reimplement proprietary
   Aurora-Lens/PEF runtime semantics.

Margaret should also identify which values must remain opaque and the permitted
implementation/licensing boundary.

## Elsa review

Elsa should explicitly mark each statement `ACCEPT`, `REVISE` or `REJECT`:

1. Authority Instrumentation supplies structured evidence about subject,
   mandate, scope, context, exposure, time, revocation and human authority.
2. A positive snapshot cannot itself produce REHT clearance.
3. Positive authority use requires current matching Kernel authority state.
4. Direct snapshots may narrow or preclude but never broaden authority.
5. Revocation is binding immediately and must also become a canonical Kernel
   update.
6. Authority/delegation/identity data is withheld from the worker projection.
7. The proposed snapshot fingerprint and workspace/context binding preserve
   Authority Instrumentation semantics.
8. The adapter remains VALO-owned and does not merge or reimplement Elsa's
   framework.

Elsa should provide the authoritative vocabulary and identify any fields that
must remain opaque references.

## Njål / VALO review

Njål or an explicitly authorized VALO owner must verify:

- state-shaping and exact-action-preclusive paths are implemented separately;
- Kernel is the only authoritative governed-state owner;
- only Kernel-admitted facts may be projected as current/confirmed;
- worker candidates, PEF frames and external inputs create no authority;
- every relevant external fingerprint is a workspace dependency;
- REHT uses fresh sealed Kernel context and an independent authorization
  clock;
- external preclusion is bound to exact action, workspace, context, purpose,
  scope and validity;
- RACS carries atomic bindings without deciding them;
- Gateway rejects mismatch/expiry before permit consumption and invocation;
- Veritas preserves provider, assessment, fingerprint and resulting decision;
- no HIGH-risk production change is merged without independent security and
  architecture review.

## Jasper / IAB blocker

Before Jasper/IAB receives a normative location, Njål must attach an owned
source or interface profile. Review must stop if the acronym, owner, scope,
validity, revocation or authority effect is unresolved.

## Evidence required to accept

- named Margaret decision on Margaret-owned semantics;
- named Elsa decision on Elsa-owned semantics;
- exact revision diff after requested changes;
- provider-neutral accepted schemas or opaque-field rules;
- cross-language canonical vectors for any binding that enters RACS;
- negative tests for stale, revoked, cross-tenant, cross-subject, changed
  fingerprint, changed workspace/context digest and authority smuggling;
- explicit permitted-use/licensing statement;
- accepted ADR with named approvers.

Until all evidence exists, status remains `draft` and the production adapters
remain optional, non-authoritative and unaccepted.
