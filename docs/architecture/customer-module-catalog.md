# Customer Module Catalog

The customer product surface is broader than software. The same ordering model can expose any repeatable, evidence-backed business outcome as a module.

A module is a reusable customer outcome recipe, not an architecture layer, not a vertical and not a limit on what the factory may do.

The ordering model is the same as the software menu:

- Ready: choose a known module and configure allowed options.
- Custom: describe the desired outcome from scratch.
- Hybrid: combine modules and add bespoke requirements.

Starter modules include:

- Custom Software — design, build, test and deliver customer-specific software.
- Shadow Discovery — scoped read-only swarm discovery that returns evidence-backed opportunities and proposals.
- Innovation — discover, prototype and validate new products, services or operating models.
- Research — answer questions with traceable evidence, uncertainty and conflicting evidence made explicit.
- Compliance — map obligations, gaps, controls and remediation work.
- Hiring — define roles, source candidates and produce evidence-backed shortlists.
- Contracting — prepare and negotiate bounded contract/document workflows under explicit mandate and approval rules.
- Procurement — research suppliers, compare evidence and prepare purchase recommendations.
- Operations — analyze and improve business processes and operating systems.
- Customer Service — create or operate governed service/support workflows.

This catalog is intentionally open-ended. New modules do not require new architecture. A new module is another recipe with objective, configurable options, required inputs, output types and acceptance criteria.

Examples:

`research + innovation -> identify market opportunity -> prototype -> software module -> production`

`hiring + contracting -> role spec -> sourced candidates -> shortlist -> approved candidate -> contract package`

`compliance + software -> gap analysis -> remediation plan -> implementation -> verification`

`shadow-discovery -> opportunities -> customer selects one -> custom/hybrid module order -> delivery`

A module order never grants authority. Customer requests, research findings, candidate data, contract drafts, supplier recommendations, code or credentials remain evidence/data. Any consequence-bearing action uses the existing execution-governance path and explicit customer acceptance where required.

The product thesis is therefore larger than a Custom Software Factory: it is a configurable customer-outcome factory whose first deeply automated production capability is software, while the same mission/evidence/governance model can support the rest of the enterprise capability menu.
