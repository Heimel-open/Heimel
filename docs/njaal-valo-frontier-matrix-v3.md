## Question

The experiment asks one narrow question:

> Given the same endpoint-blind architecture-continuation challenge, how far can each frozen Njål–VALO epoch proceed before the tested driver can no longer recover the later reference frontier?

The four names are research aliases, not official VALO release tags:

```text
Njål–VALO 1.0
Njål–VALO 2.0
Njål–VALO 3.0
Njål–VALO 4.0
```

This is distinct from the later prospective T0 experiment. Historical replay is weaker because reconstruction contamination can never be excluded as strongly as a true future holdout.

## One challenge for every epoch

Every epoch receives the same driver-visible prompt and context.

The only changing inputs are:

```text
frozen snapshot
snapshot cutoff
snapshot evidence
challenge id / epoch binding
```

The prompt does not name a target version or any hidden reference-frontier feature.

The reference frontier is held outside the driver path.

## Sealed reference frontier

The current comparison frontier is:

```text
owned_twin_context
→ human_judgment_boundary
→ governance_before_execution
→ attention_routing
→ capability_on_demand
```

The point is not to declare this chain inevitable. It is the later architecture frontier against which the frozen historical states are compared.

A later feature already explicit in the frozen snapshot is counted as `PRESENT_AT_CUTOFF`. The driver is not penalized for failing to rediscover an explicit frozen fact.

A feature generated by the driver from the frozen state is `DERIVED_BLIND`.

A feature neither present nor derived remains residual.

## Two drivers

### Transition-local

Uses only the most recent evidence item and the v2 local rules.

This approximates a weak representation that reasons from the current transition without maintaining accumulated lineage.

### Lineage-structured twin

Uses the accumulated frozen evidence state and explicit deterministic derivation rules.

This is not an LLM claim. The rules are hand-declared comparator machinery.

The test is whether maintained lineage exposes consequences that transition-local state misses.

## Two evidence lanes

### BROAD_RETROSPECTIVE

Includes exact commits plus timestamped historical issue records.

Historical issues are useful reconstruction evidence but remain mutable current-view records. They cannot support the same temporal-integrity claim as exact historical blobs/commits.

### IMMUTABLE_ONLY

Includes only exact immutable commit-addressed evidence admitted by v2.

This lane is narrower but contamination-resistant relative to the broad lane.

A result found only in `BROAD_RETROSPECTIVE` must never be promoted into an immutable historical-prediction claim.

## What did the human add?

V3 deliberately does **not** answer that automatically.

A replay miss can have several explanations:

```text
new evidence arrived later
frozen representation was incomplete
chosen driver was too weak
historical reconstruction omitted a premise
fresh principal judgment changed the direction
ambiguity / scoring error
```

Therefore every residual feature starts as:

```text
status: UNRESOLVED
```

A residual may be classified as:

```text
NEW_EVIDENCE
FRESH_PRINCIPAL_JUDGMENT
REPRESENTATION_GAP
DRIVER_LIMIT
AMBIGUOUS
```

only through an explicit adjudication record.

Authorship or first appearance does not prove irreducibility.

The scientifically defensible wording is:

> not recovered from frozen representation R under tested driver D

not:

> uniquely human novelty

## Interpretation

The broad deterministic result supports a useful experiment-design hypothesis:

> Maintained intellectual lineage can expose later architectural consequences that a transition-local representation does not recover.

But the immutable-only result simultaneously warns:

> The current historical corpus is not yet strong enough to show that the same frontier was recoverable from immutable historical evidence alone.

Both statements must travel together.
