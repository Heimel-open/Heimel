# VALO Employ shortest path to revenue

Date: 2026-06-25
Status: commercial decision note

## Decision

The shortest path to revenue is not Moltbook.

It is not marketplace.

It is not API-first.

It is not MCP-first.

The shortest path to revenue is a paid service package:

```text
Verified Agent Employ Profile Setup
```

## Why

The repo already proves enough for a buyer conversation:

- public profile
- canonical YAML
- receipts
- HMAC verification
- revenue/value record
- REP
- BARO risk
- revocation
- contestability
- write gate
- CI proof chain

That is enough to sell a controlled pilot.

It is not enough to sell a platform subscription yet.

## Buyer pain

Target buyers are already building agents and are about to lose control over:

- who owns each agent
- what each agent may do
- what each agent is forbidden to do
- what work each agent performed
- what value each agent created
- what risk each agent carries
- what evidence exists
- who is accountable

The buyer does not need a new philosophy.

The buyer needs an agent work record.

## Paid offer

Offer name:

```text
Verified Agent Employ Profile Setup
```

Buyer-facing sentence:

```text
We give your AI agent a verifiable work identity with authority, receipts, risk and accountability.
```

Deliverable:

- one verified agent profile
- canonical YAML/JSON profile
- rendered public or private profile
- authority boundary
- allowed surfaces
- blocked surfaces
- receipt templates
- risk surface
- value/revenue record
- REP score prototype
- revocation record
- contestability record
- CI proof checks
- short handover document

## Price

Start with a service price, not SaaS.

Pilot price:

```text
EUR 3,000 to 5,000
```

Small implementation:

```text
EUR 10,000 to 15,000
```

Monthly maintenance later:

```text
EUR 500 to 2,000 per month
```

Do not underprice the first pilot below EUR 3,000 unless it is a strategic reference customer.

## First buyers

Best first buyers:

- AI consultancies building agents for clients
- automation teams inside medium-sized companies
- GRC teams piloting agentic workflows
- regulated startups using AI agents
- internal platform teams with agent sprawl

Avoid first:

- big banks
- public sector procurement
- legal employment-law buyers
- HR buyers
- consumers
- broad agent marketplace users

## Why consultancies first

Consultancies already have client pain.

They need a way to prove that their agents are controlled.

They can resell the profile as part of their own delivery.

They understand why receipts, authority and risk matter.

They can pay for a packaged artifact faster than an enterprise can approve a platform.

## What to say

Use this opening:

```text
You are deploying AI agents. Before you scale them, each agent needs a work record: who owns it, what it may do, what it did, what value it created, what risk it carries, and which receipts prove it.
```

Then:

```text
VALO Employ gives an AI agent that record.
```

Then:

```text
The first implementation is agent.valo.id: a verified profile backed by YAML, receipts, risk, revocation, contestability and CI proof checks.
```

Close:

```text
VALO does not just deploy agents. VALO employs them.
```

## What to show

Demo sequence:

1. HTML profile
2. canonical YAML
3. one receipt
4. HMAC verification
5. REP/revenue/risk
6. write gate
7. GitHub Actions green
8. scope guard

## What not to show first

Do not lead with:

- Employ etymology
- Moltbook
- future marketplace
- human/team/org Employs
- full economic operating system
- API/MCP details
- legal theory

Those are second-conversation topics.

First conversation must stay on one buyer pain:

```text
Your agents need verifiable work records.
```

## Fastest build before outreach

Before outreach, build only these:

1. `profile.json`
2. `proof.json`
3. static bucket-style folder
4. one-page sales PDF or Markdown brief
5. one second sample profile if time permits

Do not build API or MCP before first outreach.

API and MCP are useful after buyer interest.

They are not required to ask for money.
