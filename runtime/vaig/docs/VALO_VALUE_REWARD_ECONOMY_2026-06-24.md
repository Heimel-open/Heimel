# VALO Value and Reward Economy

Date: 2026-06-24
Status: concept note v0.1

## Purpose

VALO should not only stop waste.

VALO should reward useful creation.

If an employee, team, or agent builds something that saves cost, reduces risk, improves quality, creates reusable capability, or opens new revenue, the system should record that value and make reward possible.

Core rule:

Do not only meter spend. Meter created value.

## Cost dimensions

AI cost is not only tokens.

VALO should track:

- model tokens
- tool/API calls
- compute time
- storage and retrieval
- human review time
- compliance review
- incident risk
- data exposure risk
- vendor lock-in
- latency and delay
- opportunity cost
- failed-agent loop cost
- duplicated work
- maintenance burden
- context pollution

A cheap model can be expensive if it creates bad work.
A costly model can be cheap if it prevents a serious mistake.

## Value dimensions

VALO should track:

- time saved
- cost avoided
- risk reduced
- quality improved
- reusable workflow created
- new data asset created
- new customer value created
- revenue enabled
- compliance evidence created
- operational resilience improved
- learning captured
- local model/context improved

Not all value is immediate cash.
Some value is future option value.

## Reward principle

People should be rewarded for useful systems, not only for using AI.

Rewardable actions:

- creating a reusable agent workflow
- reducing recurring token spend
- replacing remote calls with local model calls
- improving a prompt or policy that others reuse
- discovering a failure mode
- creating audit evidence that reduces compliance work
- building a tool that saves team time
- improving model routing quality
- increasing safe automation coverage

## Token model

VALO can support an internal value token.

Working name:

VALO Credits

A credit is not automatically a public cryptocurrency.

Recommended phases:

1. Internal points
2. Internal accounting credits
3. Redeemable rewards
4. Partner credits
5. Regulated token only if legally viable

Do not start with public crypto.
Start with auditable value accounting.

## Agent-human exchange

Agents can allocate credits to humans when humans improve the system.

Humans can allocate credits to agents or workflows when those agents create useful outcomes.

Examples:

- an agent rewards a human for correcting a policy that prevents future waste
- a human rewards an agent workflow that saves two hours per week
- a team rewards a local-model route that replaced expensive remote calls
- a governance reviewer rewards a receipt pattern that made audit faster

This creates a new internal economy:

human creativity
+ agent execution
+ measured value
+ auditable reward

## Guardrails

A reward system can be gamed.

VALO must prevent:

- fake value claims
- self-reward loops
- agent collusion
- reward farming
- inflated ROI estimates
- spam workflows
- unsafe shortcuts
- rewarding cost reduction that increases hidden risk

Required controls:

- reward receipts
- peer or manager approval above threshold
- delayed vesting for high-value claims
- clawback on false value
- separation between creator, approver, and beneficiary
- cap per period
- risk adjustment
- audit trail

## Reward receipt

A reward receipt should include:

- reward_id
- beneficiary_id
- creator_type: human, agent, team
- source_action_id
- source_receipt_id
- value_claim_usd
- value_basis
- reward_amount
- reward_unit
- approver_id
- risk_adjustment
- vesting_status
- timestamp
- payload_hash
- signature

## Positioning

VALO is not just AI cost control.

VALO is value governance for human-agent work.

It asks:

- Who had authority to act?
- Was the action worth doing?
- Which model should do it?
- Did it create value?
- Who should be rewarded?

## Key sentence

The next economy is not human versus agent.
It is human and agent value creation with receipts.
