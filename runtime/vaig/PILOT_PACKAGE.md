# VAIG Pilot Package

Status: working package  
Scope: first bounded pilot  
Audience: strategic partner, investor-advisor, enterprise pilot owner

This file controls the pilot-facing package.

It is not the EU submission package.

It is not the full research archive.

It is the minimum pilot story for testing VAIG as executable governance infrastructure.

## 1. Pilot thesis

AI governance becomes commercially real when an AI-mediated output is about to change what can happen next.

The pilot should test one bounded execution path:

```text
AI output -> EvidenceCondition -> Intent -> Authorization -> Action / Refusal -> RRP -> Receipt
```

## 2. What the pilot proves

The pilot should prove that VAIG can:

- identify an AI-mediated action path
- evaluate whether evidence is admissible before intent forms
- block or route intent when evidence is stale, contested, insufficient or contract-blocked
- issue an AARM decision
- produce a structured refusal when execution cannot continue
- assign or expose authority for next step
- preserve an accountability thread
- write a receipt / audit artifact

## 3. What the pilot does not prove

The pilot does not prove:

- that the AI output is true
- that the organization is legally compliant
- that the system is production-certified
- that every domain is covered
- that insurance acceptance is guaranteed
- that VACS / ACS is already a market standard

## 4. Minimal pilot workflow

Select one workflow only.

A good pilot workflow has:

- one AI-assisted task
- one possible consequential action
- one policy boundary
- one evidence requirement
- one human authority point
- one refusal scenario
- one receipt report

Candidate workflows:

1. AI-assisted contract / supplier review.
2. AI-assisted risk or incident summary.
3. AI agent preparing operational recommendation.
4. AI-assisted compliance or GRC review.
5. Energy / infrastructure risk report where AI output can trigger escalation.

## 5. Pilot objects

The pilot should produce these artifacts:

- ACS packet
- EvidenceCondition snapshot
- RiskContract snapshot
- AARM decision
- Refusal Object when blocked
- Authority assignment / visibility output
- Accountability thread
- Receipt
- Pilot governance report

## 6. Pilot metrics

Measure:

- total AI-mediated cases
- ALLOW count
- MODIFY count
- DEFER count
- DENY count
- STEP_UP count
- HALT count
- refusal count
- evidence-gap causes
- authority-visibility failures
- receipt completeness
- unresolved ambiguity count
- operator review latency

## 9. Frank / Svein framing

Use this framing:

VAIG is not a chatbot and not a model. It is a runtime governance layer for the point where AI output becomes action.

The repo already contains a testable governance runtime, pre-intent evidence gate, refusal lifecycle, receipt chain and ACS packet schema.

The next step is not more theory. The next step is one bounded pilot and the correct company structure.

## 10. Company structure question

The pilot discussion should answer:

- Is this an independent European AI governance infrastructure company?
- Who can open the first credible industrial pilot?
- Who advises on GRC / insurance / energy relevance?
- What must remain IP-protected?
- What is the first six-month capitalization need?

## 11. Pilot one-liner

VAIG controls the boundary where AI output becomes action and produces the evidence needed to audit what happened.
