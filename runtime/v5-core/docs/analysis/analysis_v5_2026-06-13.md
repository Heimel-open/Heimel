## 2. L1 Guardian — The Deterministic Gate (Rust)

### 2.1 State Machine (validation_logic.rs)

**4 states:** Active → Degraded → Halt → LogFullHalt

| State | Meaning | Entry Condition |
|-------|---------|----------------|
| **Active** | Normal operation | Initial state; coherent confidence within [0.42·C0, 1.06·C0] |
| **Degraded** | Elevated monitoring | Confidence outside zone OR syntax invalid OR latency bad |
| **Halt** | Execution stopped | Context age overflow OR Degraded timer expired |
| **LogFullHalt** | Terminal — log capacity | audit_log.len() >= max_log_size |

**Coherence check (THE critical formula):**
```rust
let is_coherence_valid = ai_confidence >= (0.42 * c0_threshold) 
                         && ai_confidence <= (1.06 * c0_threshold);
```

The constants **0.42 and 1.06** connect directly to Φ-law (α=0.42). This is the mathematical core.

**Fencepost fix ("gjerdestolpefeil"):**
```rust
else if self.context_age >= self.max_context_age - 1 {
    // Force DirectHalt BEFORE boundary
    self.state = ValoState::Halt;
}
```
Correctly prevents context_age from ever reaching max_context_age, eliminating the off-by-one.

### 2.2 Wire Protocol (18-byte InferenceTelemetryPacket)

```
Offset  Size  Field                  Encoding
------  ----  -----                  --------
0       8     ai_confidence_scaled   u64 big-endian (confidence × 1,000,000)
8       8     c0_threshold_scaled    u64 big-endian (threshold × 1,000,000)
16      1     syntax_valid_flag      u8 (1=valid, 0=invalid)
17      1     latency_ok_flag        u8 (1=ok, 0=too slow)
```

**Total: 18 bytes.** Big-endian for network wire format. Micro-unit scaling (×1,000,000) gives 6 decimal places of precision in fixed-point.

### 2.3 CRC32C (crc32c.rs)

- Pure Rust implementation of Castagnoli polynomial (0x1EDC6F41)
- **Compile-time lookup table generation** (`const fn generate_table()`)
- `#[inline(always)]` — zero call overhead
- Standard test vector: `"123456789"` → `0xE3069283` ✓
- Empty buffer: `0x00000000` ✓

### 2.4 Server (server.rs)

- TCP listener: `run_tcp(addr)` — `!` return type (never returns)
- UDS listener: `run_uds(path)` — same pattern
- Multiple packets per connection (inner loop)

- Terminal states break connection but server keeps running
- HMAC-SHA256 signing of every log entry
- Precision overflow check: 2^53 limit (IEEE 754)
- Flag validation: syntax_valid_flag > 1 → Halt (catches corruption)

### 5.2 client.py — ⚠️ CRITICALLY BROKEN

**THE FRAME FORMAT SENT BY client.py DOES NOT MATCH WHAT L1 EXPECTS:**

| Component | Frame Size | Format |
|-----------|-----------:|--------|
| L1 Server (Rust) | **18 bytes** | `InferenceTelemetryPacket` (2×u64 BE + 2×u8) |
| sidecar/client.py | **64 bytes** | Custom `<ddQQIII4xd8x` (legacy ValoFrame format) |

**Result:** Every request from `client.py` to L1 will fail with:
```
[ERROR] Invalid packet size: got 64, expected 18
```

The client sends a 64-byte frame with:
- Primary/secondary as little-endian f64 (not big-endian u64)
- Custom CRC32C calculation (not matching Rust CRC32C)
- Extra timestamp, identifier, checksum fields

But L1 expects exactly 18 bytes with big-endian u64 scaled values.

## 8. Critical Bugs Found

### 🔴 BUG-1: sidecar/client.py Frame Format Mismatch (CRITICAL)

**Impact:** Client completely non-functional against L1

**Details:**
- `client.py` sends 64-byte frames via `struct.pack("<ddQQIII4xd8x", ...)`
- L1 expects 18-byte `InferenceTelemetryPacket`
- L1 checks `raw_bytes.len() != expected_size` → rejects with HALT
- The CRC32C calculated in Python also doesn't match Rust CRC32C (different polynomials/implementations)

**Fix:** Rewrite `_exchange()` to use 18-byte format:
```python
import struct, time

def _exchange(self, sock, primary, secondary):
    # Scale to micro-units (matches L1 expectation)
    conf_scaled = int(secondary * 1_000_000)
    c0_scaled = int(primary * 1_000_000)
    frame = struct.pack(">QQBB", conf_scaled, c0_scaled, 1, 1)
    sock.sendall(frame)
    resp = sock.recv(4)
    codes = {0: "ALLOW", 1: "DEGRADED", 2: "HALT", 3: "LOGFULLHALT"}
    return codes.get(resp[0], "HALT") if resp else "BYPASS_MODE"
```

### 🔴 BUG-2: tests/test_bridge.py Tests Wrong Frame Format (CRITICAL)

**Impact:** All unit tests would fail if run

**Details:**
- Tests import `_crc32c` and `_FRAME_FMT` from `bridge.py` — **these don't exist**
- Tests expect 64-byte frame output from `pack_valo_frame()`
- Actual `pack_valo_frame()` returns 18 bytes (delegates to `pack_telemetry_packet`)

**Fix Options:**

2. **Restore 64-byte frame format** in bridge.py (would need L1 changes too)
