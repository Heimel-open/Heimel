# Relygon device compatibility

## Product hypothesis

A person's Relygon becomes more useful as it gains more legitimate, governed access to the person's actual digital and physical environment.

The objective is not maximum surveillance or unrestricted access. It is maximum useful access under the person's control: explicit mandate, transparent observation, least-necessary disclosure, provenance, revocation and governed consequence paths.

This creates a new hardware selection criterion:

**How much better can my life become with Relygon on this device?**

A phone, computer, wearable, vehicle, headset, appliance or home system is therefore not evaluated only by its own specifications. Its value also depends on how well it can participate in the person's persistent intelligence environment: what it can expose, observe, sense and execute for Relygon under governed authority.

## Compatibility classes

### Relygon Relevant

The device or service can contribute useful signals, observations or capabilities to Relygon, but does not implement the full Relygon interoperability contract.

Typical properties:
- useful data or capability exists
- access may depend on vendor APIs, exports or adapters
- integration can be partial or read-only
- provenance and scope must still be preserved before information becomes admissible Relygon evidence

### Relygon Compatible

The device or service implements defined Relygon contracts and can participate as a governed, replaceable peripheral or capability provider.

Typical properties:
- stable schema adapter / interoperability contract
- authenticated source identity
- observation, evidence, capability and/or effect envelopes as applicable
- explicit scope and mandate
- provenance, timestamps and uncertainty preserved
- revocable access
- no direct write into canonical personal state
- no direct consequence path outside governed authorization
- conformance tests can verify compatibility

Compatibility does not make the device part of Relygon identity. The device remains replaceable infrastructure.

### Relygon Optimized

The device is deliberately designed to maximize useful Relygon participation while preserving the person's control and the Relygon continuity boundary.

Potential properties:
- deep local observation interfaces
- high-quality application and UI interaction signals
- continuous sensor access where explicitly authorized
- local processing and privacy-preserving filtering
- low-latency governed action across apps, sensors and hardware
- hardware-backed identity / attestation
- granular capability and observation permissions
- transparent indication of what Relygon is observing or doing
- strong revocation and physical disable mechanisms
- efficient local model / NPU / GPU access where useful
- first-class Relygon schema support rather than reverse-engineered adapters

`Relygon Optimized` is a prospective ecosystem / hardware designation, not a claim that such a certification program currently exists.

## Strategic consequence

Hardware becomes part of the capability surface.

Two otherwise similar devices may have materially different value to a person because one gives their Relygon better governed access to applications, conversations, sensors, context and execution capabilities.

This means openness to personal intelligence can become a purchasing criterion alongside battery life, camera quality, compute, price and industrial design.

The long-term ecosystem objective is:

**Relygon Relevant → Relygon Compatible → Relygon Optimized**

The progression measures not how much a vendor can learn about the person, but how effectively the person's own Relygon can use the device for that person under governed authority.

## Boundary

More access is valuable only when control remains with the person.

Therefore:

**greater access without governance is not optimization.**

A Relygon-optimized device must increase useful capability without transferring ownership of identity, continuity, personal state or authority to the device vendor.
