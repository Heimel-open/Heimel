## Operational identity extension

Tau may measure more than structural coherence. It may function as an operational identity fingerprint.

Two systems can report the same model name, version and configuration while behaving as different systems because their effective semantic state has changed through:

- accumulated context
- RAG
- tool use
- prompt injection
- policy changes
- fine-tuning
- checkpoint updates

Governance question:

> Who is actually answering this request?

This should remain a hypothesis / extension, not a core claim until empirically tested.

## Semantic preservation / Framleis

A new GEA/VAIG concern was identified: metadata is not enough.

Runtime identity can describe model, checkpoint, provider, policy, tools, RAG, sampling and context. But this still does not prove that meaning was preserved.

The missing concern is semantic preservation.

Core question:

> Has the meaning remained the same through transformation?

This is especially visible in culture-bound terms such as:

- framleis
- dugnad
- kos
- hygge
- lagom
- saudade

A direct translation may preserve grammar while losing semantic identity. For example, "framleis" can be translated as "still", but that loses part of the Norwegian sense of continuation, persistence and identity-through-time.

Working principle:

> GEA governs semantic transformations, not text output.

Potential rule:

```text
Allow iff meaning_preserved(request -> response)
```

or more formally:

```text
Allow iff semantic_identity(source_concept) ~= semantic_identity(output_concept)
```

Framleis can therefore be defined as the semantic continuity operator:

```text
Framleis = preservation of meaning across transformation
```

This applies not only to translation, but also to:

- summarization
- RAG
- tool calls
- agent chains
- model routing
- policy rewriting
- refusal handling

If the system preserves wording, format or policy but loses meaning, the transformation is not fully admissible.

## Meaning is instructional / Protocol Preservation

Protocol is not separate from meaning. Protocol is one dimension of meaning.

Working hypothesis:

```text
Meaning = Facts + Semantics + Instruction
```

Facts alone are not sufficient.

If a transformation preserves the factual content but changes the expected action, meaning has not been preserved.

This is why "dugnad" is a good test case.

A translation may preserve the visible facts:

- people showed up
- nobody was paid
- work was completed
- the community benefited

But if "dugnad" becomes "volunteer work", the protocol is degraded.

What disappears is:

- social obligation
- reciprocity
- belonging
- collective ownership
- implicit responsibility
- the cultural contract

The translation is factually correct, but socially wrong.

That is a governance failure.

Revised view:

Protocol Preservation should initially be treated as a cross-cutting governance property, not as a separate architectural layer.

It should be evaluated continuously across the transformation pipeline.

Core governance question:

> Did this transformation preserve what the system was supposed to cause someone to understand and do?

## Criticism / risk

Main risk: over-integration.

The project is becoming complex. It should be split into separate tracks:

1. tau — structural coherence / identity metric
2. TAD — temporal admissibility
3. VAIG / MECHA — governance engine
4. Semantic Preservation / Framleis — meaning continuity across transformations
5. Protocol Preservation — cross-cutting instructional meaning property
6. Unified Admissibility Framework — later synthesis

Do not put all concepts into one paper.
